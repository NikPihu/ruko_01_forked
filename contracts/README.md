Current version: **`c2-0.3`** (see the changelog at the end; c2-0.1 and c2-0.2 requests still validate). The response and `GET /health` both carry `contract_version`.

## POST /v1/decide

Called once, when the user taps Pay. The server answers in 200 ms or less. The client should also
give up after its own short timeout and let the payment go through (fail open, T0).

### Request
| Field | Type | Notes |
|---|---|---|
| `request_id` | string | a new UUID per Pay tap; echoed back in the response |
| `user_id` | string | demo: `u_demo_meena` |
| `payee_upi_id` | string | **plain** UPI ID (not hashed). It's needed for the NPCI / bank / registry lookups. The payee's ID is not the user's private content. |
| `amount_inr` | number > 0 | |
| `entry_method` | `typed` \| `qr` \| `contact` \| `collect` | how the payee was entered |
| `payer_says` | optional: `government` \| `company` \| `family` \| `shop` \| `investment` \| `other` | answer to "Who are you paying?" |
| `ts` | ISO 8601 **with timezone**, e.g. `2026-11-07T10:40:00+05:30` | |
| `context` | object or `null` | `null` = the user opted out of phone signals |

`context` holds only flags derived on the phone. SMS text, audio, contacts and screen content are never sent.
- `call`: `active`, `kind` (`sim`\|`voip`), `direction` (`incoming`\|`outgoing`), `caller_number`, `caller_in_contacts`, `started_min_ago`, `ended_min_ago`
- `device`: `remote_access_active`, `remote_app_installed_min_ago`, `untrusted_accessibility`, `sideloaded_last_24h`
- `episode` (c2-0.3): the task-scam episode the phone's background watcher keeps for up to 30 days across all payees and UPI apps (bank SMS + this app's payments). `state` (`none` \| `watching` \| `active` \| `dismissed`), `age_days`, `bait_credits`, `bait_inr`, `outs`, `outs_inr`, `new_payees`, `escalation_steps`, `last_out_inr`, `out_to_in_ratio`, `payee_seen_in_episode`, `rules_version`. Rules: `episode_rules.json`; shared test cases: `examples/episode_vectors.json`. Bait fields are `null` when SMS can't be read; `episode` is `null` when the watcher is off. The engine counts it as **one lure-family signal**.
- `money` (c2-0.2, **deprecated**, accepted until c2-0.4): the payer's own money flow over the last 72 h, counted on the phone from the app's payments and bank SMS alerts. Only counts and sums leave the phone. `bait_credits` (small credits of Rs 500 or less from UPI IDs the user never paid), `credits_inr`, `debits` (not counting this one), `debits_inr`, `new_payees`, `escalation_steps` (run of payments each at least 1.5x the one before, up to the latest), `last_debit_inr`. Credit fields are `null` when SMS checks are off.
- `lures`: list of `{tag, conf 0–1, min_ago}`. The tag is one of `arrest_threat`, `kyc`, `task_job`, `trading_tip`, `refund`, `normal`.

**Unknown ≠ safe:** a signal the phone did not or could not measure must be `null` (or left out).
It must never be `false` or `0`. For example, if call-state permission was denied, send
`"caller_in_contacts": null`, not `true`.

Unknown fields are rejected with **HTTP 422**. Treat a 422 like any other failure: fail open.

### Response
| Field | Type | Notes |
|---|---|---|
| `request_id` | string | echoed |
| `tier` | `T0`–`T4` | T0 go to PIN · T1 inline tip · T2 explain card · T3 pause + trusted contact / 1930 · T4 analyst review |
| `reasons` | list of codes | show up to 3, in order; empty for T0 |
| `message_key` | string or null | `t1_tip`, `t2_generic`, `t3_generic`, or `<tier>_<playbook>` such as `t3_digital_arrest` |
| `pause_minutes` | int | 30 for T3, 60 for T4, else 0 |
| `playbook` | string or null | `digital_arrest`, `fake_customer_care`, `fake_kyc_apk`, `trading_group`, `task_job`, `refund_qr` |
| `stage` | `S0`–`S5` or null | journey stage (contacted → hooked → under control → paying → paying again) |
| `evidence_id` | string or null | id of the evidence record, if one was written |
| `fail_open` | bool | true = RUKO could not decide in time; the payment proceeds |
| `contract_version` | string | |

The score is never sent. Show reasons in words (Hindi + English), never a number.

Reason codes: `R1_live_unknown_call`, `R2_remote_control`, `R3_mule_like_payee`,
`R4_unusual_amount`, `R5_lure_message`, `R6_new_payee_typed`, `R7_tranche_pattern`,
`R8_intel_hit`, `R9_story_mismatch`, `ruko_unavailable`. If the app doesn't recognise a code, it
should skip it and never show it raw.

## For the Android app: current gaps vs `net/Models.kt`
These are what the app needs to change to stop getting 422s:
- `payee_vpa_hash` → `payee_upi_id` (plain). `PAYEE_SALT` is then not needed on the phone.
- Add `request_id` and `entry_method`. Remove `payee_typed_manually`, which is covered by
  `entry_method: "typed"`.
- Flat `context{on_call, call_minutes, …}` → nested `context.call` / `context.device` / `context.lures`.
  Field defaults should be `null`, not `false` / `true`.
- `lure_tags` → `context.lures`, each with `min_ago`.
- Response: drop `case_id`; add `playbook`, `stage`, `fail_open`, `contract_version`;
  `pause_minutes` is always present.

## Changing the contract
1. Edit `backend/schema/events.py` and bump `CONTRACT_VERSION`.
2. `PYTHONPATH=backend:ml:data python -m schema.export`
3. Update the examples here, then `pytest backend/tests`.
4. Tell the Android owner which fields changed. All of this goes in one commit (CLAUDE.md rule 8).
